1. AmiiboAPI
------------

Catalogue row (README line 1263):

| [AmiiboAPI](https://amiiboapi.com/) | Nintendo Amiibo Information | No | Yes | Yes |

(A) Documentation evidence
- https://amiiboapi.org/docs/ (HTTP 200 on 2026-11-17) contains:
  "This is a reading-only API. Only HTTP GET method is allowed by this API."
  "No authentication is required to use this API. All resources are allowed to access."
  => supports Auth = No.
- https://github.com/N3evin/AmiiboAPI (archived official repository) lists
  https://www.amiiboapi.com/ as its homepage and uses Flask-Cors. The pinned
  requirements file contains "Flask-Cors==4.0.2":
  https://raw.githubusercontent.com/N3evin/AmiiboAPI/master/requirements.txt
  => supports CORS = Yes.
- Note on provenance: https://amiiboapi.com/docs/ returned unrelated
  promotional content during this check, so it was not used as documentation
  evidence. The .org mirror above and the GitHub repository were used instead.

(B) Live HTTP observations (curl, 2026-11-17T14:38Z window)
- GET https://amiiboapi.com/ -> HTTP 200 over HTTPS
  => HTTPS = Yes is supported.
- GET https://amiiboapi.org/api/amiibo/ -> HTTP 200, header
  "Access-Control-Allow-Origin: *"
  => CORS is enabled on the working API deployment.
- GET https://amiiboapi.com/api/amiibo?name=mario -> HTTP 404
- GET https://www.amiiboapi.com/api/amiibo?name=mario -> HTTP 404
  => The .com API paths were not serving responses at check time, while the
  .org deployment was. This is an availability inconsistency, not a metadata
  correction. It does not justify changing Auth/HTTPS/CORS or removing the
  entry.
- An earlier checker HEAD https://amiiboapi.com/ timed out after 10 seconds
  (classification: Timeout); a later run returned HTTP 200 (classification:
  Success). A manual GET also succeeded. No GET fallback is performed for a
  timeout because the checker only falls back for HEAD 405/501. The variation
  is recorded as a point-in-time availability observation.

Conclusion: keep Auth = No, HTTPS = Yes, CORS = Yes. No README change.

  repository is https://acnhapi.com/doc, which could not be retrieved because
  the service did not respond.
  => CORS remains Unknown.

- curl --http1.1 GET http://acnhapi.com/ -> curl: (52) Empty reply from server

  connection without response"), classification: Network Error.
